## 二、系统是什么

一套面向公共学习空间（图书馆、自习室、教室）的**智能选座与导航一体化系统**，三层结构：

```
感知层   ESP32 + 超声波传感器        →  实时判断座位是否有人，公网上报
云端层   Flask + MySQL + Socket.IO   →  座位调度、预约鉴权、路径规划、AI 服务
移动层   Android（Capacitor 封装）+ Vue 3  →  选座、预约、室内外导航
```

公网访问地址：https://zhinengzuo.site

## 四、原创部分说明（重点）

以下内容由本团队自主设计与实现，是本作品的核心：

### 4.1 系统架构与数据模型
- 三层架构（感知 / 云端 / 移动）的划分与接口约定
- 数据模型设计：学校 → 建筑 → 楼层 → 座位 → 传感设备 / 预约 / 用户，
  含多校隔离与四级角色（学生 / 普通用户 / 学校管理员 / 管理员）

### 4.2 座位占用判定规则
- 超声波模式下「距离小于阈值判有人」的判定逻辑
- **离线释放策略**：设备超时无上报视为掉线；且离线判定只在报告为「无人」时生效，
  避免「长时间无上报后又收到一条空报告」把已占用座位错误回退
- 区分「未接入传感器」与「传感器故障」两类状态（这条同时是 AI 的诚实性约束）

### 4.3 室内导航（零信标定位方案）
- **路网数据结构**（节点 + 边的 JSON 格式）与管理员手绘路网的存储方案
- **A\* 启发式寻路**：启发函数为节点间欧氏距离；就近吸附逻辑
- **跨楼层路径拼接**：按楼梯口 / 电梯口节点连接各层路径
- **路网三级兜底**：已存文件 → 按座位坐标生成 → 按图尺寸铺兜底网格（只驻内存）
- **断点自动搭桥**：路网断成多块时，用最短的一条边把最近的缺口连起来
  （只改内存邻接表，不写回磁盘，管理员画的线不动）
- **PDR 连续定位**（本作品的核心创新）：
  - 以座位上已有的**二维码为绝对坐标锚点**，扫码即完成一次定位
  - 用手机**加速度计做步态检测**：阈值不是写死的常数，而是
    **泄漏式最小值包络 + 固定余量** —— 跟着设备静止水平自适应，
    不会被走路峰值带跑（真机实测：写死 13.5 时一步都不记，
    改用低通滤波后又会被峰值抬高、走十几步只记 8 步，最终改成现在这版）
  - 用**磁力计 / 陀螺仪估计朝向**；位置只在「检出一步」时积分
  - 提供**比例尺标定入口**（像素/米），换平面图后可按实际尺寸重标
  - 与规划路径比对，偏离超阈值时提示重新扫码校准

### 4.4 室外导航
- 未配置地图密钥 / 地图服务不可用时，**自绘「相对方位图」**：
  以用户为圆心，各目标建筑按真实方位角与真实距离摆放，带距离刻度圈，
  完全不依赖任何外部服务
- 定位优先走原生桥（Capacitor 插件），再退回浏览器 API
- 加载高德 SDK 时声明步行路线插件，并对失败原因做分类提示

### 4.5 移动端原生能力封装
自行封装的 7 项原生能力（`static/js/native-*.js`）：
- **扫码占座**（相机 + 二维码识别 → 选座 / 签到）
- **语音选座**（系统语音识别 → 本地意图解析 → 找座 / 预约 / 导航；
  座位号正则做了区号处理；**设备无语音识别服务时可退化为文字输入**，
  复用同一套意图解析，保证该功能在任何手机上都能演示）
- **实时提醒**（本地通知：预约到期、座位释放；**Android 13+ 会先申请运行时权限**，
  否则系统静默丢弃通知而接口照样返回成功）
- **地理围栏**（基于建筑经纬度，进入 / 离开推送）
- **传感器导航**（上述 PDR）
- **离线缓存**（接口响应写本机，断网可看）
- **桌面快捷方式**（找空座 / 扫码占座 / 我的预约 / 语音选座；动作经 URL 参数传递）
- 统一的浏览器降级策略：同一套代码在网页里打开不报错，原生功能自动退化为安全返回
- 移动端外壳（顶栏 / 底部 Tab / 侧边抽屉 / 悬浮按钮长按拖动）；
  **AI 悬浮球与语音按钮都可单独隐藏**（设置面板里两个开关）
- 悬浮按钮长按拖动的位置记在本机，下次打开沿用

### 4.6 AI 应用层
- **AI 智能体（工具调用）**：让大模型真的能查数据、能操作系统
  - 只读工具 5 个：列场所楼层 / 楼层统计 / 查座位 / 找空位 / 查设备在线
  - 写工具 3 个：开放·关闭座位 / 开关红外 / 关整层红外
  - **写操作必须二次确认**：模型只能「提议」，由前端弹确认卡片，
    用户点了才落库 —— 模型理解偏了也不会误改数据
  - 提示词要求：意图不明确时先问清楚，不要自己猜一个操作就提议
- **AI 诚实性设计**：把「数据的可解释边界」当作设计对象 ——
  未接入传感器的座位不参与离线统计，推送给模型的快照中显式区分
  「未接入传感器」与「传感器故障」，并要求模型不得混淆。
  目的：让 AI 在数据不足时如实说「不知道」，而不是编一个看起来合理的结论。
- 座位推荐理由、终端大屏一句话结论、管理端运营简报等提示词设计

### 4.7 硬件方案
- ESP32 固件流程：Wi-Fi 配网 → 向云端注册 → 周期拉取配置（座位号 / 阈值 / 上报间隔）
  → 测距判定 → HTTP JSON 上报；含断线重连与配置自动恢复
- **超声波模块 3.3V 单电源直连方案（免分压电阻）**：
  常规做法是 5V 供电 + 分压电阻保护 3.3V GPIO；本团队通过**回环自检**
  （短接 TRIG 与 ECHO，捕获到 14µs 脉冲，证明 GPIO 与中断通路正常）与实机对比，
  确认 `VCC→3V3、TRIG→GPIO16、ECHO→GPIO27` **直连即可稳定出数**，
  减少两个元件、两个焊点与一类故障源

### 4.8 界面与交互
全部页面（用户端、管理端、智能终端）的界面设计、交互流程与样式，
包括移动端外壳、实时座位图的分色与筛选、导航页的路径渲染与传感器导航面板等。

### 4.9 自动化测试
455 项测试用例的设计与编写，覆盖接口、权限、导航寻路、传感判定、AI 工具权限、
前端静态体检等。其中「前端静态体检」用于拦截一类难排查的问题：
模板中绑定的方法在脚本里并不存在 —— 这类错误会被事件回调静默吞掉，
表现为「按钮点了没反应」。

## 六、AI 辅助编程使用声明

按大赛通知第（二）条要求如实说明：

| 项目 | 说明 |
|---|---|
| 是否使用 AI 辅助编程 | **是** |
| 所用 AI 模型及版本 | **DeepSeek**（deepseek-chat 系列模型） |
| AI 生成代码占比（估算） | **约 50%**（按代码行数估算，含补全与改写的部分） |

| 团队自主设计与实现 | 见第四节「原创部分说明」全部条目 |
| 团队复核情况 | **所有 AI 参与的代码均经团队成员逐行阅读、修改与实测验证后方才合入**；核心算法与业务规则由团队自行编写 |

管理后台可现场切换服务商与模型，支持接入本地部署的模型服务。
发送给模型的仅为座位状态统计与结构化快照，**不含用户姓名、学号等个人身份信息**。

## 七、运行与部署

### 7.1 服务端
```bash
pip install -r requirements.txt
cp .env.example .env          # 填写数据库、AI、地图等配置
python setup_db.py            # 初始化数据库
python app.py                 # 开发模式，监听 0.0.0.0:5800
```

生产模式（本项目云端实际用法）：
```bash
pkill -f "venv/bin/gunicorn"
cd /www/wwwroot/seatnav
./venv/bin/gunicorn -k eventlet -w 1 -b 0.0.0.0:5800 app:app --daemon
```

### 7.2 移动端
```bash
cd mobile
npm install
npx cap sync android
cd android && ./gradlew assembleRelease
```

### 7.3 硬件端
```bash
cd DEMO
pio run -t upload            # PlatformIO，ESP32 dev 板
```
接线：HC-SR04 `VCC→3V3`、`TRIG→GPIO16`、`ECHO→GPIO27`（直连，免分压）

### 7.4 测试
```bash
python -m pytest tests -q     # 455 项
```

### 7.5 打包云端更新 / 源代码包（本团队自用）
```bash
python make_cloud_pkg.py      # 只打「与云端不同」的文件
python make_source_pkg.py     # 打参赛用的完整源码包
```
