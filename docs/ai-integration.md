# 大模型 AI 集成说明

> 智能选座与导航一体化系统 —— AI 体验层（用户端 / 管理端 / 智能终端）

## 1. 设计原则（重要）

### 1.1 算法定事实，AI 做表达

座位是否被占用，**始终由传感器 + 规则引擎判定**（确定性、可复现、可测试）。
大模型**不参与占用判定**，只负责两件事：

1. 把结构化事实**翻译成人话**；
2. 从历史数据里**发现模式**。

> 为什么：若让大模型读原始数据自行判断，它会幻觉编造"某座位空闲"，
> 对着界面核对一次就会露馅。分离职责后，AI 的输出永远以真实数据为锚。

### 1.2 三层可用性保障（答辩/演示不怕断网）

| 层级 | 条件 | 行为 |
|------|------|------|
| ① 在线 API | 配置了 API Key 且网络可达 | 大模型生成自然语言 |
| ② 本地模型 | 指向 `http://127.0.0.1:11434/v1`（Ollama 等） | **完全离线**也能用 AI |
| ③ 规则降级 | 未配置 / 调用失败 / 超时 / 限流 | 自动输出规则文案，**绝不报错、绝不白屏** |

每个接口都返回 `ai_generated` 字段，前端据此显示"大模型生成"或"规则模式"标签。

### 1.3 数据新鲜度优先

当所有座位都长时间无上报（设备/网络整体掉线）时，系统**不会**给出
"现在很空"这类误导性结论，而是明确提示数据已过期并给出排查建议。
快照中的 `data_stale` / `last_report_minutes_ago` 字段即用于此。

## 2. 架构

```
ESP32 / 传感器
      ↓ 原始上报
规则引擎（Seat.status 判定）          ← 占用事实来源
      ↓
【状态快照 Snapshot】(utils/ai_context.py)   ← token 控制关键：50 座位 → 数百 token
      ↓
【LLM 服务层】(utils/llm.py)
   ├─ OpenAI 兼容协议（供应商可切换）
   ├─ 结果缓存（默认 60s，防重复调用）
   ├─ 超时 / 退避重试 / 鉴权失败快速放弃
   └─ 失败一律返回 None → 调用方降级
      ↓
【AI 业务层】(utils/ai_service.py)
   ├─ UserAIService   用户端
   └─ AdminAIService  管理端
      ↓
HTTP 接口 (app.py)  →  终端大屏 / 管理页 / 嵌入式设备
```

### 文件清单

| 文件 | 职责 |
|------|------|
| `utils/llm.py` | LLM 客户端：协议、缓存、重试、降级、状态 |
| `utils/ai_context.py` | 状态快照 + 用户画像 + 提示词组装（控 token） |
| `utils/ai_service.py` | 用户端/管理端 AI 能力 + **全部规则兜底文案** |
| `templates/terminal.html` | 智能终端大屏页（零 CDN 依赖） |
| `templates/admin/ai.html` + `static/js/admin/ai.js` | 管理端 AI 运营中心 |
| `tests/test_ai.py` | 48 项测试（含降级、缓存、密钥不泄露、配置合并） |

## 3. 供应商切换（可在页面操作，无需重启）

支持预设：`deepseek` / `openai` / `qwen`（通义）/ `zhipu`（智谱）/ `custom`。

**方式 A：管理后台（推荐）**
管理后台 → **AI 运营中心** → 选择供应商 → 填 API Key → 保存。
保存后立即重建客户端生效，无需重启服务。

**方式 B：`.env`**

```bash
AI_ENABLED=true
AI_PROVIDER=deepseek          # deepseek / openai / qwen / zhipu / custom
AI_API_KEY=sk-xxxxxxxx
# AI_MODEL=deepseek-chat      # 留空用预设默认
# AI_BASE_URL=                # 留空用预设默认；custom 必填
AI_TIMEOUT=20
AI_MAX_TOKENS=600
AI_CACHE_TTL=60
```

**本地模型（离线演示）**

```bash
AI_PROVIDER=custom
AI_BASE_URL=http://127.0.0.1:11434/v1
AI_MODEL=qwen2.5:7b
AI_API_KEY=ollama            # Ollama 不校验，随便填非空值
```

> ⚠️ **密钥安全**：仓库是公开的。密钥只写入 `data/system_config.json`
> （已在 `.gitignore` 中）或 `.env`（同样已忽略）。接口只返回"是否已设置"
> 与掩码，**绝不回传明文**（有测试守护）。

## 5. 智能终端（Kiosk）

**做法**：本机浏览器打开 `http://127.0.0.1:5800/terminal`，按 **F11** 全屏，
即成为一块"智能终端大屏"。

特点：

* **零外部依赖**：页面不引用任何 CDN（Vue/字体/图标全不用），断网也能正常渲染；
* 显示内容：AI 一句话结论、空闲/占用统计、上座率、座位实时色块网格、时钟；
* 每 10 秒自动刷新，连接失败会显示重试状态而非空白；
* 数据过期时指示灯转红并显示"数据延迟 N 分钟"。

**嵌入式终端（可选）**：ESP32 + OLED 可轮询极简接口

```
GET /api/ai/brief?max_len=32
→ {"text":"全馆14座空闲11…","free":11,"total":14,"ai_generated":true}
```

## 6. 管理端 AI 运营中心

路径：管理后台 → **AI 运营中心**（`/admin/ai`）

* **AI 状态**：在线/降级模式、供应商、模型、调用统计（请求/缓存命中/降级次数）
* **模型配置**：切换供应商、填 Key、调超时/生成上限/温度/缓存，保存即生效
* **运营简报**：自然语言现状 + 分楼层 + 异常
* **异常发现**：设备掉线/传感器故障的**有序排查建议**
* **趋势解读**：基于历史上报数据的每日占用率趋势
* **运营问答**：自然语言提问（附快捷问题）
* **终端入口**：一键打开大屏页 + 嵌入式接口说明

## 7. 成本与性能控制

| 手段 | 说明 |
|------|------|
| 状态快照 | 把 N 个座位压成计数 + 楼层分布 + 少量明细，prompt 从数千 token 降到数百 |
| 结果缓存 | 相同请求 60s 内直接命中（默认），避免轮询打爆 API |
| `max_tokens` 上限 | 单次生成封顶（默认 600），防跑飞 |
| 超时 + 有限重试 | 默认 20s 超时 / 2 次退避重试；401/403 立即放弃不浪费 |
| 空闲座位号截断 | 快照最多列出 20 个空闲座位号 |

## 8. 测试

```bash
python -m pytest tests/test_ai.py -q     # 48 项 AI 测试
python -m pytest -q                      # 全套 119 项
```

覆盖要点：

* LLM 客户端：未配置静默返回 None、缓存命中、网络异常降级、
  鉴权失败不重试、响应格式兼容、状态不泄露密钥
* 快照：计数/上座率正确、全局离线识别、指纹随状态变化
* 降级文案：数据过期时诚实提示、无空座提示、异常座位列举
* 接口：公开/需登录/需管理员权限边界、终端页零 CDN、
  配置校验（非法供应商/地址/超时）、**保存 AI 配置不丢失其它配置**（回归）
