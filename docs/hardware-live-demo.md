# ESP32 占座传感器 —— 真机演示与自测操作指南（HC-SR501 / PIR）

> 目标：**读完这份，你自己就能把一台装有 HC-SR501（人体感应）传感器的 ESP32 连到主系统，看到真实占用/释放，并能在答辩/汇报里演示。** 不需要懂复杂原理，按步骤照做即可。原理层面的说明见 `docs/hardware-integration.md`。

> ⚠️ **你现在用的是 HC-SR501（PIR 人体感应模块）**。整份指南都按它来讲。你**不用改固件代码**——首次用设备热点填 WiFi+服务器地址，之后到 `/admin/hardware` 的「设备管理」把“传感器类型”选成 **HC-SR501（高电平）** 并绑定座位即可。

---

## 0. 先搞清楚：你要演示哪种形态

| 形态 | 数据来源 | 适合场景 |
|---|---|---|
| **A 真机** | ESP32 每 5 秒上报传感器读数 → 主系统判定 → 前端实时变色 | 答辩主推（"物联网感知"硬核点） |
| **B 模拟兜底** | 主系统自带"传感器模拟器"，后台按钮随机翻转座位 | 硬件临时故障时的保底演示 |

> 物理连通就一句话：**设备通过 WiFi 访问"主系统电脑的 IP:5800"的接口。** 把第 3 步的服务器地址填对、设备和电脑同一个 WiFi、电脑防火墙放行 5800，就通了。

## 1. 需要准备的材料

**硬件**
- 1 块 ESP32 开发板（如 ESP32 DevKit，USB 供电）
- **HC-SR501（PIR 人体感应模块）**，推荐 2 个（一个接 `GPIO23`、一个接 `GPIO27`）
  - 想省事也可**只用 1 个**：把它的 `OUT` 同时接到 `GPIO23` 和 `GPIO27`，两个读数永远一致（见第 2 步）
- 杜邦线若干（HC-SR501 的 VCC / OUT / GND 接到 ESP32）
- 1 根 USB 数据线（连电脑烧录 + 供电）
- 一台电脑（跑主系统） + 一台手机或另一台电脑（打开前端页面看效果）

**软件**
- VS Code + **PlatformIO** 插件（编译/烧录 ESP32），或命令行 `pip install platformio`
- Python 3.9+（跑主系统）
- 主系统源码目录：`D:\MAX_xiangmu`

## 2. 接线（HC-SR501，按这张表插）

| HC-SR501 引脚 | 连到 ESP32 | 说明 |
|---|---|---|
| `VCC` | **5V**（若无 5V 引脚可接 3.3V） | HC-SR501 工作电压较高，5V 更稳 |
| `OUT`（信号，第 1 个） | `GPIO23`（→ `ir_front`） | 检测到人体时输出 **HIGH** |
| `OUT`（信号，第 2 个） | `GPIO27`（→ `ir_back`） | 两个传感器各接一个引脚 |
| `GND` | `GND` | 两个传感器共地 |

- **只用 1 个 HC-SR501** 时：把唯一的 `OUT` **同时接到 `GPIO23` 和 `GPIO27`**，这样 `ir_front` 与 `ir_back` 始终一致，一个传感器也能触发占用。
- 两个传感器**交叉放置**（一个朝座椅前侧、一个朝后侧，各约 45°），人坐下/坐下过程有动作 → 上报 `(1,1)`。
- HC-SR501 是 **PIR 人体感应**：检测到**人体移动**时输出 `HIGH`。到 `/admin/hardware` 的「设备管理」把该设备的“传感器类型”选成 **HC-SR501（高电平）** 即可（见第 3 步）。
- 接好后给 ESP32 上电，板载 LED 亮/闪即正常。**自检**：用手在传感器前晃动，HC-SR501 的 OUT 会在 `HIGH`↔`LOW` 间跳变（可在串口看，见第 6 步）。

> HC-SR501 顶部有 **2 个电位器**（灵敏度、延时）+ **1 个跳线**（触发模式）。用于"座位占用"请按第 10 节附录调：灵敏度调到能覆盖座位范围，**延时调到最小**，跳线选 **H（可重复触发）**。

## 3. 首次连接：用“设备热点”配置（一次，不用改代码）

新固件**不需要你改 `main.cpp`**。你只让设备连上网 + 知道服务器地址，之后座位/传感器类型/间隔都在**管理面板**改。

**① 给 ESP32 上电**（接好传感器，或先不接）——它首次会开热点 **`ESP32-Config`**。

**② 手机连它**：手机连 WiFi `ESP32-Config`（无密码）。

**③ 打开配置页填表**：手机浏览器进 **`192.168.4.1`**，填三样：
- WiFi 名称 / 密码（你路由器的）
- 服务器地址：`http://<你电脑局域网IP>:5800`（`ipconfig` 看 IPv4）

点“保存并连接”。设备会保存并自动连接，**随即注册到主系统**（用 WiFi MAC 作设备号）。

**④ 到管理面板绑定**：打开 `/admin/hardware` → 设备上线会提示“🆕 新 ESP32 已注册成功”，下方「**设备管理**」出现它。在这里给它**绑定座位、选传感器类型（HC-SR501=高/红外=低）、设上报间隔**，保存——之后设备拉取配置即生效，**不用重烧、不用改代码**。

> 说明：WiFi + 服务器地址只能在这个“设备热点”表单里填一次（设备必须先连上网才能找到服务器，这是没法绕过的物理边界）。**换座位 / 传感器类型 / 上报间隔**，以后都在 `/admin/hardware` 面板改。

## 4. 启动主系统（每次演示前这样做）

**① 关掉传感器模拟器**（很关键，否则随机数据会和真机互相覆盖）

编辑主系统目录下的 `.env`，加入一行：

```
SENSOR_SIMULATOR_AUTOSTART=False
```

> 或者主系统起来后，用管理员调 `POST /api/admin/simulator/stop`。二选一。

**② 让主系统监听所有网卡 + 端口 5800**

```bash
python app.py 0.0.0.0 5800
```

- 首次运行防火墙会弹窗，选"允许（专用 + 公用 网络）"，否则 ESP32 访问不到。
- 启动日志会打印 `局域网访问 http://192.168.x.x:5800`，**记下这个 IP，用于第 3 步设备热点表单的“服务器地址”**。

> 数据库说明：主系统默认尝试连 MySQL；连不上自动回退 SQLite，演示照跑。Redis 不装也会自动退化为单进程模式，不影响演示。

## 5. 先在主系统里建好"要绑定的座位"

1. 管理员登录 → 管理端 → 建筑/楼层 → 创建一栋楼和一个楼层。

3. 记下它的**座位标签 `seat_label`**（就是平面图上的编号，如 `A区-12`）。
4. 到 `/admin/hardware` 的「设备管理」，给该设备**绑定这个座位**（见第 3 步）。

## 6. 烧录固件并看串口

```bash
cd DEMO
pio run -t upload        # 第一次会自动下载工具链，耐心等
pio device monitor       # 波特率 115200
```

串口应看到：

```
[WiFi] 已连接，IP = 192.168.x.x
[HTTP] POST http://192.168.x.x:5800/api/sensor/report -> {"seat_label":"A区-12","ir_front":0,"ir_back":0}
[HTTP] 上报成功 HTTP 200（ir=(0,0)）
```

- 手在传感器前晃一下，串口的 `ir_front/ir_back` 应出现 `1`（±几秒内）。
- `上报失败 HTTP 404` → 座位标签填错；`HTTP -1 / 连接超时` → 主系统没 `0.0.0.0` 启动 / 不同 WiFi / 防火墙没放行 5800（核对 `SERVER_URL` 的 IP 和端口）。

## 7. 前端看真实占用 / 释放

1. 手机或另一台电脑浏览器打开 `http://<主系统IP>:5800` → 登录**用户端** → 进「**座位图**」页。
2. 让一位同学**坐到/靠近**你绑定的座位：`(1,1)` → **≤5 秒**座位图变**红**（占用）。
3. 同学离开、传感器检测不到人体动作后：连续两次"无人"上报 → 约 **10 秒**变回**绿**（释放）。
4. 锁定、预约、导航照常可用；座位图**无需刷新**（WebSocket 实时推送）。

> ⚠️ PIR 特性提醒：**HC-SR501 侦测的是"人体移动"，不是"静止占座"。** 有人坐着不动超过 HC-SR501 的延时（默认几秒到几十秒），它会从 `HIGH` 掉回 `LOW` → 座位可能短暂显示空闲。演示时（人坐下、离开）动作足够，可忽略；若要增强，把 HC-SR501 延时电位器调到**最小**（见第 10 节）。

## 8. 演示脚本（答辩 / 汇报照着念）

1. 打开「座位图」页，展示当前座位全是绿色（空闲）。
2. 请一位同学坐下 → 讲："这是**真实传感器**上报，前端 **5 秒内自动变红**，无需刷新页面。"
3. 同学离开 → 讲："连续两次'无人'上报，约 **10 秒自动释放**变回绿色。"
4. （加分项）占用满 m 分钟后，在座位弹窗点「锁定」，讲解 **m/n 动态防抢座**；再演示**室内导航**导航到该座位。
5. 收尾强调："整条判定/锁定/导航链路都在主系统完成，设备端只做持续扫描+上报，软硬件解耦。"——正好呼应"物联网感知"定位。

## 9. 常见问题速查

| 现象 | 排查 |
|---|---|
| 串口 `上报失败 HTTP 404` | 设备绑定的座位标签与实际座位不一致（或座位不存在） |
| `HTTP 400`，提示"匹配到多个座位" | 同名标签跨楼层，填 `FLOOR_ID` 消歧 |
| `HTTP -1` / 连接超时 | 主系统是否 `0.0.0.0` 启动；ESP32 与电脑同一 WiFi；防火墙放行 5800 |
| 人坐下座位不变红 | 设备“传感器类型”是否选成 **HC-SR501(高电平)**；看接线与串口 `ir=(1,1)` 是否出现 |
| `ir` 一直 `0`，手晃动也没反应 | HC-SR501 的 VCC 电压不够（接 5V）、OUT 没接对、或没上电 |
| `ir` 一直 `1`，人走了也不变 | HC-SR501 延时太长/环境干扰；把延时跳到最小；或人走后多等，通常 2 个上报周期后释放 |
| 人坐下一会儿就变绿 | PIR 只侦测"移动"，静止太久会掉线 → 调小 HC-SR501 延时电位器（见第 10 节） |
| 座位频繁闪红/绿 | 传感器模拟器还在跑，先停（第 4 步）；或 HC-SR501 受热源/气流干扰 |
| 座位显示**异常**（灰/叹号） | 设备连续停止上报超过 `SEAT_OFFLINE_HOURS`；恢复供电会自动转回正常 |

## 10. 附录

**HC-SR501 的关键设置（改动前先调它）**
- HC-SR501 顶部有两个**电位器**和**一个跳线**：
  - **延时电位器（Time）**：调到**最小**（逆时针到底）。否则人坐下后 HC-SR501 会持续输出一段时间 HIGH，人走了也不马上释放。
  - **灵敏度电位器（Distance）**：调到能覆盖你座位周围即可，太大易误报、太小侦测不到。
  - **跳线**：选 **H（Repeat，可重复触发）**，这样有人持续动作时会不停重触发；选 L 则一次触发后要等复位。
- HC-SR501 对**热源/气流/阳光**敏感，尽量远离空调、电视屏、窗边。

**红外避障 vs PIR（两种传感器怎么选）**
- **红外避障模块**：检测到物体时输出 LOW，适合"座椅是否被占"；在面板「设备管理」传感器类型选 **红外避障(低电平)**。
- **PIR（HC-SR501）**：检测到**人体移动**时输出 HIGH，适合"是否有人"；传感器类型选 **HC-SR501(高电平)**。缺点是不识别静态占座（需配延时/灵敏度）。
- 你现在是 HC-SR501 → 面板里选 **HC-SR501(高电平)**。

**没有真机时怎么演示（兜底 B）**
- 启动主系统后，管理员调用 `POST /api/admin/simulator/start` 开启模拟器；或保持 `SENSOR_SIMULATOR_AUTOSTART=True`。
- 再用 `POST /api/admin/simulator/occupy`（带 `seat_id` + `occupied`）手动把某个座位翻成占用/空闲，前端同样实时变色，也可演示锁定/导航。
